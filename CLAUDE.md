## What This Is

PulseBoard is a serverless telemetry platform for open-source projects. It tracks real deployments (not just GitHub clones) — versions, OS, geography, feature usage, cost, errors, and performance. The backend is Python 3.12 Lambdas + DynamoDB, deployed via AWS SAM. The dashboard is a vanilla JS SPA served from S3/CloudFront.

## Build and Deploy

```bash
# Full deploy (build Lambdas + deploy infra + upload dashboard)
./deploy.sh

# First-time / reconfigure
./deploy.sh --guided

# Dashboard-only (HTML/JS/CSS changes — skips Lambda build)
./deploy.sh --dashboard-only

# Build Lambdas without deploying
sam build --template template.yaml
```

There are no tests, linters, or local dev servers configured. Changes are verified by deploying to AWS.

## Architecture

**Four Lambda handlers**, all in `src/handlers/`, sharing `src/shared/` utilities:

- **ingest.py** — `POST /ingest`. Public endpoint, API key auth (not Cognito). Validates key via DynamoDB GSI, writes raw event to EventsTable, atomically updates day/week/month counters in AggregatesTable.
- **projects.py** — CRUD for projects + Cognito user management (`/projects/*`, `/admin/*`). All endpoints require Cognito JWT. Admins get full API keys; Viewers get masked values.
- **stats.py** — Dashboard data API (`/stats/{id}/*`). Reads from AggregatesTable for fast pre-computed stats. The `breakdown` endpoint also scans EventsTable for per-deployment unique counts.
- **github_traffic.py** — Scheduled (every 6h) + manual (`POST /github/fetch`). Fetches GitHub API traffic data and stores permanently (GitHub only keeps 14 days).

**Three DynamoDB tables** (all PAY_PER_REQUEST):

- `pulseboard-projects-{stage}` — PK: `project_id`, GSI on `api_key` for ingest lookup
- `pulseboard-events-{stage}` — PK: `project_id`, SK: `timestamp_id` (ISO + UUID suffix), GSI on `event_date`
- `pulseboard-aggregates-{stage}` — PK: `pk` (project_id), SK: `sk` (period keys like `day#2026-03-23`, `week#2026-W12`, `month#2026-03`, `github#summary`, `ghday#2026-03-23`)

**Dashboard** (`dashboard/`): Single-page app using Tailwind CSS (CDN) + Chart.js. No build step. Auth is raw Cognito API calls (no AWS SDK). `config.js` is generated by `deploy.sh` — do not edit manually, it's gitignored.

**SDK** (`sdk/pulseboard.py`): Zero-dependency Python client using only stdlib. Fire-and-forget via daemon thread. Generates stable machine fingerprint from `SHA-256(hostname + platform info)`.

## Key Design Decisions

**Cost event separation**: Events with `.cost` suffix (e.g. `image_studio.cost`) only update `total_cost_usd` in aggregates — they don't increment event counts or inflate model/version/OS breakdowns. The paired action event (e.g. `image_studio.generate`) handles those. This prevents double-counting.

**Aggregate update is two-step**: `_increment_aggregate` in ingest.py first ensures the DynamoDB item + empty maps exist (idempotent SET with `if_not_exists`), then increments counters. This avoids nested map initialization issues in DynamoDB.

**Version/OS/country breakdowns use "latest per deployment"**: The breakdown endpoint tracks each `distinct_id`'s most recent event values, not cumulative counts. This shows "currently running" versions, not "ever used."

**CloudFront routing**: CloudFront serves the dashboard (S3 origin) by default, and routes `/ingest`, `/projects*`, `/admin/*`, `/github/*`, `/stats/*` to API Gateway. All API routes have caching disabled.

## Handler Conventions

- All handlers use the same pattern: single `handler(event, context)` entry point, path-based routing via `event["path"]`
- Imports use `sys.path.insert` to resolve `src/shared/` — this is required because SAM copies files flat
- `shared/response.py` provides `ok(body)`, `error(msg, status)`, and `parse_body(event)` — always use these for API Gateway responses
- `shared/db.py` provides lazy table accessors (`events_table()`, `projects_table()`, `aggregates_table()`) reading table names from env vars
- DynamoDB numeric values use `Decimal` (required by boto3), convert with `_dec()` for int or `_dec_float()` for float
- Aggregate updates use atomic DynamoDB operations (SET with `if_not_exists` + ADD for sets) — never read-modify-write

## Dashboard Conventions

- All JS is vanilla (no framework, no bundler). Global objects: `PBAuth` (auth.js), `PBCharts` (charts.js), inline IIFE in app.js
- `PBAuth.api(path, opts)` handles JWT auth + auto-refresh on 401
- Period filtering uses `_currentDays` (0=lifetime, -1=custom range, positive=days back) and `_buildDateParams()` to construct query strings
- Auto-refresh fires every 5 minutes when tab is visible; pauses when hidden; refreshes on tab focus if data is stale (>1 min old)
